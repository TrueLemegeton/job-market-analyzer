# Job Market Analyzer

Личный сервис для анализа рынка IT-вакансий.

Проект был создан как практический Python-проект для сбора, обработки и анализа вакансий Python-разработчиков с HH.ru.

Проект остановлен на текущем этапе после получения основного практического опыта и выявления недостатков в подходе к его разработке.

## Цель проекта

Создать собственный инструмент, который позволяет анализировать рынок Python-вакансий на основе большого количества реальных данных.

Изначально планировалось использовать собранные данные для анализа:

* наиболее востребованных технологий;
* наиболее часто встречающихся навыков;
* требований к Junior, Middle и Senior разработчикам;
* зарплат;
* изменения спроса на технологии со временем;
* навыков, которые стоит изучать для развития в Python-разработке.

Основная идея проекта — работать с собственными собранными данными, а не полагаться только на общие оценки и предположения.

## Что реализовано

В проекте реализованы следующие компоненты:

* поиск Python-вакансий на HH.ru;
* сбор ссылок на вакансии;
* получение страниц отдельных вакансий;
* извлечение названия вакансии;
* извлечение зарплаты;
* определение `gross` / `net` для зарплаты;
* извлечение названия компании;
* извлечение требуемого опыта работы;
* извлечение типа занятости;
* извлечение графика работы;
* извлечение формата работы;
* извлечение формата оформления;
* извлечение ключевых навыков;
* нормализация полученных данных;
* приведение различных полей вакансии к единому виду;
* подключение PostgreSQL;
* описание структуры базы данных с помощью SQLAlchemy;
* создание таблиц базы данных;
* сохранение обработанных вакансий в PostgreSQL;
* интеграция LLM для определения уровня вакансии;
* интеграция LLM для дополнительного анализа навыков вакансии.

## Архитектура проекта

Общая схема pipeline:

```text
HH.ru
   ↓
Playwright
   ↓
Поиск вакансий и сбор ссылок
   ↓
Requests
   ↓
Получение HTML страниц
   ↓
BeautifulSoup
   ↓
Извлечение структурированных данных
   ↓
Нормализация
   ↓
PostgreSQL
   ↓
LLM-анализ
   ↓
Определение уровня и дополнительных навыков
```

## Установка

### 1. Клонирование репозитория

```bash
git clone https://github.com/TrueLemegeton/job-market-analyzer

cd job-market-analyzer
```

### 2. Создание виртуального окружения

```bash
python -m venv .venv
```

### 3. Активация виртуального окружения

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Windows CMD:

```cmd
.venv\Scripts\activate
```

### 4. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 5. Установка браузера для Playwright

```bash
playwright install chromium
```

### 6. Запуск

```bash
python src/main.py
```

## Статус проекта

**Проект остановлен.**

Он не был доведён до первоначально задуманного конечного состояния и больше не развивается.

В процессе разработки я получил практический опыт работы с:

* парсингом и обработкой данных;
* PostgreSQL;
* SQLAlchemy;
* построением pipeline;
* интеграцией LLM;
* структурированием данных;
* взаимодействием нескольких компонентов приложения.

При этом проект показал несколько проблем в моём подходе к разработке.

### Основные выводы

**1. Разработка началась слишком рано**

В начале проекта я сразу перешёл к написанию кода, не продумав архитектуру, этапы и конечную структуру системы.

Из-за этого некоторые решения принимались уже в процессе разработки, когда проект становился сложнее.

**2. Слишком большая зависимость от AI**

На начальном этапе я писал большую часть кода самостоятельно.

После появления новых и более сложных технологий я начал значительно больше делегировать AI: написание кода, отдельные решения и реализацию компонентов.

Это позволило быстрее двигаться вперёд, но одновременно уменьшило количество решений, которые я принимал самостоятельно.

**3. Не было чётких промежуточных этапов**

У проекта не было достаточно чётко определённых контрольных точек.

В результате новые функции добавлялись поверх уже существующей системы, постепенно увеличивая её сложность.

**4. Приоритеты определялись по ходу разработки**

Вместо последовательного движения от минимально работающей версии к расширению функциональности проект постепенно обрастал новыми задачами.

Это привело к тому, что часть времени уходила на исправление и переосмысление уже сделанных решений.

**5. Не была заранее определена достаточная граница проекта**

В определённый момент стало понятно, что дальнейшая доработка будет приносить меньше полезного опыта, чем переход к следующему проекту с другим подходом к планированию.

Поэтому проект был остановлен.

## Итог

Этот проект не стал законченным продуктом, но стал важным практическим этапом обучения.

Основной результат проекта — не только реализованные компоненты, но и понимание собственных слабых мест в процессе разработки.

В следующих проектах я планирую сначала определить:

```text
Цель
↓
MVP
↓
Архитектура
↓
Этапы разработки
↓
Реализация
↓
Проверка
↓
Расширение
```

Дальнейшая разработка `Job Market Analyzer` не планируется.
